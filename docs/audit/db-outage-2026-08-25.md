# DB connectivity incident — 25 Aug 2026, ~06:50 IST

## Symptom
Every sign-in and portal page failed with `getaddrinfo ENOTFOUND db.datosorvtxtxtcvqboxv.supabase.co`.
`/api/health` returned 500; the app was effectively down in dev.

## Diagnosis (scripts/db-connect-check.mts)
- The hostname resolves **AAAA-only** (no IPv4 A record).
- Node's `dns.lookup` on this machine returns ENOTFOUND for it even though
  resolve6 works — getaddrinfo's default family preference filters out the
  AAAA record when no IPv6 route exists.
- TCP probe to the IPv6 address times out: this host has no usable IPv6 route
  to Supabase.
- Control: `aws-0-ap-south-1.pooler.supabase.com` (the Supavisor pooler)
  resolves to IPv4 addresses and is TCP-reachable on :6543.

Root cause: the Supabase project lost its IPv4 add-on (Supabase removed
free IPv4 support / the dedicated IP expired), so the direct-connection
hostname is IPv6-only. This machine cannot reach IPv6, so every direct
connection fails. The app worked before because either the machine had an
IPv6 route or the project still had IPv4.

## Immediate fix for local dev
Switch DATABASE_URL to the pooler hostname, which is dual-record:

```
DATABASE_URL=postgresql://postgres.<PROJECT_REF>:<PASSWORD>@aws-0-ap-south-1.pooler.supabase.com:6543/postgres
```

(Password = the DB password from Supabase → Project Settings → Database;
the ref for this project is `datosorvtxtxtcvqboxv`. Keep
`uselibpqcompat=true`; drop `sslmode=require` — node-postgres handles TLS
via its ssl option.)

Note: the pooler username format differs (`postgres.<ref>`, not `postgres`)
and prepared statements must be disabled — drizzle's node-postgres driver
works over the transaction pooler as-is because pg disables prepared
statements when `prepare: false`… verify with scripts/db-connect-check.mts
after editing .env, then run `npm run db:migrate && npm run db:seed` if the
database was reset while paused.

## Longer term
1. Check the Supabase dashboard: if the project shows "paused", restore it —
   free projects pause after 7 days of inactivity (see docs/decisions.md D1).
2. Re-add the IPv4 add-on if direct connections are needed from
   IPv4-only networks.
3. Consider pointing local dev at PGlite (unset DATABASE_URL) so offline/
   paused-DB states don't block UI work: `npm run db:migrate && npm run db:seed`
   against embedded PGlite.
